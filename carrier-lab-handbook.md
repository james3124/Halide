# Carrier Lab Handbook
**Parent: 07-telephony-modem-data.md**

## 1. Scope and authority
Operational handbook for the radio bench: SIM fleet, cell/band fixtures, drive-test discipline, contact log, and blessing-campaign scheduling for REF-A/B. Test-execution gates live in ch.07 §§15/22–23 and ch.10 §§7/18–19; this file owns the *bench hygiene* that makes those gates believable. Owner Telephony; QA audits SIM/fixture logs quarterly. All radio logs redacted (cell IDs + signal numbers committable; IMSI/IMEI never committed — ch.09 §4 redacted-only rule applies to every artifact below).

## 2. Lab SIM fleet management
Inventory (`lab/sim-inventory.csv`, offsite-backed per ch.10 §27 3-2-1 rule): columns `iccid-last4,carrier,plan(IMSI-live/test-desk),unit-binding,holder,state(active/suspended/lost),expiry,monthly-bill-code`. Rules: one SIM ↔ one labeled unit binding at a time (binding changes logged with timestamp + reason + operator — undocumented swaps invalidate radio results per ch.10 §18 leave-no-trace rule); prepaid/test-desk SIMs preferred for soak/stress (live-billed SIMs only for blessing + drive-test windows); data caps monitored (mid-campaign throttling invalidates throughput rows — cap alerts page Telephony before the run, not after); lost-SIM response ≤24h (carrier suspend via §5 contact log + inventory `lost` + incident per ch.10 §11 lab-infra; stolen-with-unit follows ch.10 §27 unit-loss path). Quarterly reconciliation (physical SIMs vs CSV vs carrier portal lines, owner Telephony, 1h in the ch.10 §22 hygiene hour — missing SIM = incident, not mystery). No personal SIMs in gating units (personal-SIM runs tagged `INFORMAL`, non-gating).

## 3. Cell/band fixture inventory
Fixtures (`lab/rf-fixtures.md` + photo per bench): RF-shield bag (negative-control duty per ch.10 §24 — bag-attenuation spot-checked quarterly with a known-good unit, dead bags replaced not debated), callbox or cooperative small-cell where available (cell identity + band + firmware recorded per run — fw is a dimension per ch.10 D2, dashboards split by it), band-lock profiles (`lab/band-profiles/<carrier>-<bands>.json`: lock commands + expected MCC/MNC + fallback-unlock procedure — every locked run names its profile, unlocked runs state `UNLOCKED` explicitly so band-ambiguity never hides in a footnote), cable/attenuator set (labeled loss values, calibration stickers current or runs tagged `UNCALIBRATED` per ch.10 §22). Booking ties fixture to unit (ch.10 §18 `lab/CALENDAR.md` entry names unit + rig + SIM identity + expected return state charged ≥60%; soak `DO-NOT-TOUCH` tags physical + calendar). Fixture failures exit 2 infra-flake (ch.10 §7 contract — callbox power-loss mid-soak extends the booking automatically per §18 contention fairness, never silently retried).

## 4. Drive-test discipline
When callbox/SIM-lab is insufficient (handover, urban-canyon GNSS-adjacent radio behavior, carrier-requested routes): route card first (`lab/drive-tests/<date>-<carrier>.md`: route GPX, bands under test, phone mount + power (USB-PD meter logging per ch.10 §3 1Hz rule where feasible), stock-oracle companion unit mounted identically — same-unit-comparison honesty per ch.10 §20 extends to same-drive comparison). Roles: driver (never touches phones) + operator (starts `data-soak.sh`/`call-loop.sh`/`gnss-track.sh` slices, notes timestamps for tunnels/bridges/dead-zones). Safety: local traffic-law compliance + mount legality check pre-drive (illegal mounts cancel the drive — no result is worth impound); emergency-dial live tests never piggyback on drives (emergency-call-certification §5 authorization stands alone — drive routes use LAB numbers/callbox replay unless a separate PSAP ticket exists). Post-drive: redacted logs only (GPX with home/work endpoints truncated 200m, cell IDs kept, IMSI stripped by `--redact` before commit), `INVALID-RERUN` marking for weather/route mismatches vs oracle (ch.10 §20 honesty — mismatched drives re-driven, not footnoted-away). Two drives minimum per blessing campaign (weekday + off-peak, same route — single-drive blessing evidence rejected in review).

## 5. Carrier contact log
Single file (`lab/carrier-contacts.md`, access-controlled, offsite-backed): per carrier `carrier,account-team,test-desk,blessing-engineer,noc-escalation,contract-or-MOU-id,response-SLA`. Every carrier-affecting event logged within 24h (SIM suspend/loss, blessing finding P0/P1, rollout-halt with radio signature per ch.09 §§20/26, drive authorization, PSAP ticket cross-refs to emergency-call-certification matrix). Log hygiene: ticket ids + dates + owner per entry (entries without next-action-owner bounce in weekly Telephony standup); portal credentials rotated quarterly with `lab/access.md` keys (ch.10 §18 rotation); no carrier-debug blobs with subscriber PII committed (redaction gate from §1 enforced by the same upload-job grep as ch.10 §7 scripts). Relationship rule: test-desk courtesy windows honored (≤5 live emergency-adjacent calls/day unless authorized — emergency-certification §5 restated here because drive days tempt extra calls); missed courtesy = incident with apology note, not silent retry.

## 6. Blessing-campaign scheduling
Entry bar (no slot booked without): emergency LAB-ONLY matrix green on the candidate RC (emergency-certification §3), radio gates green on both REFs (ch.07 §§22–23 attach/setup/drop/stall numbers), power/soak sheets current (ch.10 §§8/15/20 comparison report drafted), two-builder repro + testkey-grep green (ch.09 §§2–3 — carriers asked to bless testkey builds burn trust permanently). Campaign timeline (per carrier, 3-week template in `lab/blessing-<carrier>-<ver>.md`): W-2 submit entry pack (matrix slice + FW/MANIFEST SHAs + OTA staged 1/10/50/100% + health-gate summary); W-1 lab session (band-lock matrix + handover/recovery + drive #1); W0 fixes (hotfix lane ch.09 §21 clock where carrier deadline binds, else monthly train); W+1 drive #2 + close-out (blessed / conditional-<id> / fail-<id> with re-test scope). Results publish to release notes CARRIERS line (ch.09 §14) and ch.10 D2 radio dashboard (fw-split, per §19 source discipline). Post-blessing FW freeze: blessed FW pinned for the release (FW bump post-blessing restarts blessing per ch.07 §23 + emergency-certification §2 invalidation — "same except modem" is a new blessing, stated here so schedule pressure can't waive it).
