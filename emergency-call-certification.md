# Emergency Call Certification
**Parent: 07-telephony-modem-data.md**

## 1. Scope and non-claims
Covers voice emergency routing verification for HALIDE on REF-A/B: SIM-present, SIM-absent (SOS-only), roaming, and airplane-toggle recovery paths. Does not claim carrier certification or regulatory approval; claims are limited to executed protocols in §2 with redacted logs only (versions, timestamps, setup cause codes — no IMSI/IMEI in committed artifacts, ch.09 §4 discipline). Any region/carrier/SKU tuple without a passing record is labeled UNTESTED per §4, without exception for "should work like neighbor region."

## 2. Per-region emergency routing verification protocol
Region table (`telephony/emergency-matrix.csv`, normative): columns `region,sku,numbers_tested,sim_state,roaming(Y/N),fw_ver,result,date,psap_coord_id_or_LAB-ONLY`. Numbers per region минимум: US 911, EU 112, UK 999+112, JP 110/118/119, AU 000+112, plus carrier-specific routing where the carrier profile names one (carrier-profile-example governs). SIM states per tuple: provisioned SIM, expired/prepaid-zero-balance SIM, no-SIM SOS-only (Zion-device must camp SOS per 3GPP — no-SIM refusal is P0), locked-screen dialer path (lockscreen-5 record discipline reused: 5 consecutive emergency dials from lock without unlock or unlock-bypass bug).

Execution per tuple (lab callbox preferred; live-network only under §5 PSAP coordination): (1) camp check (`qmicli --nas-get-serving-system` + MM state, record MCC/MNC + band), (2) place call via Telecom emergency path (never direct ATD bypass — bypass passes hide routing bugs), (3) record setup time (dial→alerting ≤10s lab, live-network ≤20s or P1), audio both-ways 20s, location-indication presence (AML/QMI position-fix-sent flag where modem exposes — absence logged, not faked), (4) release with normal cause + re-camp ≤60s (airplane-recovery gate ch.07 §22 reused), (5) redacted report (`telephony/emergency/<region>-<sku>-<date>.md` with footnote set per ch.10 §12). Modem FW change invalidates all rows for that SKU (fw is a dimension per ch.10 D2 — re-bless required, same rule as ch.07 §23).

## 3. Carrier blessing interaction
Carrier blessing campaigns (schedule owned by carrier-lab-handbook) consume this file's matrix as entry evidence: no blessing slot booked without all target-region LAB-ONLY rows green on the shipping RC. Deliverables to carrier lab: emergency matrix slice + redacted setup-time histogram + SIM/no-SIM results + FW SHA + MANIFEST.lock SHA + rollback/OTA health-gate summary (A/B OTA with health gates + staged 1/10/50/100% stated so carriers see post-ship fix path). Carrier findings map to P0 (emergency setup fail, no-SIM SOS refusal, lockscreen bypass) / P1 (setup >20s, one-way audio, re-camp >60s) with 7-day dogfood + 72h soak re-run on fix per ch.10 §§10/15 (emergency fixes ride ch.09 §21 hotfix lane with 24h clock where the carrier deadline requires). Blessing status per SKU published in release notes CARRIERS line (ch.09 §14) as `blessed / conditional-<id> / UNTESTED` — never "pending" without the blocking item named.

## 4. UNTESTED labeling enforcement
Label locations (all three, or the label is missing): Settings → About → Regulatory (`Emergency: TESTED <regions> / UNTESTED <regions>` built from the matrix at image assemble time, ch.09 §8 `halide-assemble-lxc` version-consistency pattern reused — matrix/ROM mismatch refuses first-boot banner rather than shipping a stale claim); retail box/traveler sticker (`factory-traveler-template.md` emergency line: tested regions checked, rest struck as UNTESTED with initials); release notes CARRIERS + COMPAT lines (ch.09 §14 — UNTESTED regions named explicitly). Build-time enforcement (`scripts/emergency-label-lint.sh`, per-MR + release blocking): matrix CSV parses, every shipped SKU has ≥1 row, label strings in the image equal matrix contents for that MANIFEST, any `TESTED` claim without a green row fails with the tuple named. Relabel without retest is a process P0 (same severity as ch.09 §15 wrong-key doctrine — label lies strand users in emergencies). Dogfood units crossing into UNTESTED regions during travel file a P2 observation (roaming emergency behavior noted, never live-tested without §5 coordination).

## 5. Test-call scripting with PSAP coordination notes
Lab-first rule: all automation in `tests/emergency/` runs against callbox/RF-shield by default (`emergency-dial-test.sh --lab`: iterates matrix numbers, asserts camp + setup-cause + 20s bearer + re-camp, redacted log, exit 0/1/2 contract per ch.10 §7). Live-network test calls are never scripted blind: require written PSAP/test-desk authorization (ticket id recorded as `psap_coord_id` in the matrix — LAB-ONLY rows carry no id and are never presented as live evidence), scheduled window (off-peak, ≤5 calls/carrier/day unless the carrier authorizes more), pre-call announcement script ("Non-emergency handset test, authorization <id>, will release in 20 seconds, call back <number>"), immediate release + callback-availability 10 min post-call, and no-SIM live tests only where the PSAP explicitly authorizes SOS-absent origination (otherwise no-SIM stays LAB-ONLY — unauthorized SOS calls are unlawful in most regions and a project-ending trust breach).

Script contents (`tests/emergency/emergency-dial-test.sh --live --auth <id>` wrapper, human-attended, never CI-automated against live networks): pre-flight (SIM state, MCC/MNC, FW SHA, battery ≥30% per ch.09 §9 OTA battery discipline reused for test-call readiness), per-number dial/verify/release/re-camp with 60s spacing (back-to-back emergency redials flag abuse filters — spacing is load-bearing), post-flight redacted report + PSAP confirmation note (test-desk ack or voicemail timestamp). Violations (unauthorized live call, script run without `--auth` against live MCC) file a conduct P0 + quarantine the involved unit's results for 30 days (ch.10 §6 quarantine discipline applied to process, not just code).
