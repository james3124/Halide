# 06 — Graphics: DRM/KMS, Mesa & SurfaceFlinger→Wayland Bridge
**Budget: 70,000 chars · Phases: 1–2 · Owner: Graphics · GPUs: Adreno/Freedreno first, Mali second**

## 1. Stack & ownership

Host owns DRM master (Phosh/phoc +-mutter stack on `drm-backend`). Android SurfaceFlinger runs headless inside container, compositing app layers into buffers shared via `dma-buf` + `binder` fence FDs; `halide-composer` on host imports them as Wayland surfaces (one `wl_surface` per Android window). No nested X. No second DRM master (would `-EBUSY`).

```
Android app → SurfaceFlinger (container) → dma-buf FD ─┐
Phosh apps → Wayland → phoc ───────────────────────────┼→ DRM/KMS → panel
halide-composer (imports FD, respects fences, presents) ┘
```

## 2. Driver matrix

- REF-A Adreno: `msm` DRM + Freedreno + Turnip (Vulkan) + `freedreno` Mesa. Pin Mesa version in manifest; record `glmark2-es2-drm` + `vulkaninfo` baseline.
- Mali REF-B: Panfrost/Valhall or vendor blob (timeboxed). If blob required, isolate to container EGL with host passthrough documented as tech-debt + upstreaming issue link.
- Fallback: `simpledrm`/software (llvmpipe) must always boot to Phosh (slow but debuggable) — gate: no panic without GPU firmware.

Validation per SKU: `modetest -M msm -s <conn>@<mode>`, `kmscube`, `glmark2-es2-wayland`, 200-frame `frame_timeline` with <5% drops.

## 3. halide-composer protocol

- Window mapping: Android `Task` → Wayland `xdg_toplevel` (title = app label, app_id = `android.<package>`).
- Buffer exchange: `AHardwareBuffer` → `dma_buf` import via `zwp_linux_dmabuf_v1`; explicit fencing (`sync_file`) mandatory — no tearing-allowed flag in v1.
- Input: host Wayland → Android `InputFlinger` via `/run/halide/input` socket (touch slots, pressure, palm). Rotation: host owns orientation sensor; Android forced `nosensor` + resize (no independent rotation v1).
- Lifecycle: Android pause/resume slaved to `wl_surface` visibility (occluded 500ms → `onPause` hint to save power).

Perf gates: touch→photon <100ms (high-speed camera or `evtest`→`frame_callback` timestamp diff), 60fps scroll in F-Droid list, 1 Android video (720p) + 1 native video concurrently without underrun.

## 4. Display details

Panel timings from ch.02 DT; backlight via `phosh` slider → writes both `backlight` class and Android `LightsService` (so Android brightness slider, if opened, follows). Night-light: host `gammastep` owns LUT; Android Night Light disabled/hidden v1. AOD: off v1 (document power reason).

Multi-window v1: one maximized Android window + native windows; split-screen Android+Linux is Phase-4 stretch (record as non-gate).

## 5. Debug & failures

| Symptom | Check | Fix |
|---------|-------|-----|
| Android window black, native OK | `halide-composer --debug`, `dumpsys SurfaceFlinger` | fence never signals (driver sync bug) → force `sync_file` wait with timeout + dump |
| Tearing in Android video | `drm_info`, fence timeline | missing explicit fence import; enable `DMA_BUF_SYNC` + verify |
| Touch offset/rotated | `evtest` vs `wayland-info` geometry | input transform matrix per panel rotation; store in `hw/<sku>/input-matrix.conf` |
| Whole-device freeze on rotate | `dmesg \| grep -i panel/dsi` | DSI link re-train missing; lock rotation during video v1 workaround with bug ID |
| `failed to import dmabuf: Permission denied` | cgroup/device ACLs | LXC device allowlist missing `dri/renderD128`; fix config, not chmod 777 |

Tools: `wayland-info`, `drm_info`, `perfetto` (Android), `sysprof` (host), `kmscube --gpu`, screenshot via `grim` (host) + `screencap` (container) for A/B comparison.

## 6. halide-composer implementation (normative)

Language: C++17 + `wayland-client` + `libdrm` + `libsync`; no toolkit dependency (must run before Phosh fully up — splash path). Threads: binder-listener (receives layer list + buffer FDs + fences from SurfaceFlinger proxy), wayland-present (imports + `frame_callback` driven), input-forward (touch/keyboard to `/run/halide/input`), watchdog (stall detector: no present for 2s while visible → dump fence timeline + `dumpsys SurfaceFlinger` + restart hint, never silent black).

Buffer import path (exact): receive `dma_buf` FD + stride/format/modifier + `sync_file` acquire fence → `zwp_linux_dmabuf_v1.create_params` → `wl_surface.attach` → `wl_surface.damage` (dirty rects from layer list, not full-frame — power rule) → `wl_surface.commit` → wait `frame_callback` → close release fence back to producer. Modifier negotiation: query compositor (`phoc`) supported modifiers at startup via `dmabuf.modifier` events; reject buffers with unsupported modifiers with a structured error (format+modifier logged) instead of corrupt present. AFBC/compression modifiers per-SKU allowlist in `graphics/<sku>/modifiers.conf` — stock camera-preview modifiers must be in the list or preview goes black (common bring-up failure, §9).

Fence discipline: every buffer carries an acquire fence; composer `poll()`s with 500ms timeout; timeout → (1) dump `sync_file` info + last 3 fences, (2) present previous good frame with `HALIDE-FENCE-STALL` marker in debug overlay, (3) count toward stall metric. Release fence returned on `frame_callback`. Zero-fence buffers rejected in v1 (no tearing-allowed) — the day someone asks for a tearing flag, that MR must include the power/tearing tradeoff measurement or it is closed.

Layer mapping detail: SurfaceFlinger `DisplayDevice` (one virtual display, 1:1 with panel mode) → layers sorted by Z → each Android `Task` with visible window gets `xdg_toplevel` (app_id `android.<package>`, title = task label, parent = none v1); system UI layers (status bar, nav) are NOT forwarded (host owns chrome — no double status bars, ever; Android SystemUI inside container is configured `config_showNavigationBar=false` + status bar suppressed via overlay `config_statusBarComponent`).

## 7. Input pipeline (touch you can trust)

Path: kernel `evdev` (multitouch slots A/B) → libinput (host) → Wayland → `halide-composer` hit-test (Android surface under finger?) → `/run/halide/input` socket (binary protocol v1: `TOUCH_DOWN/UP/MOVE slot x y pressure major tool-type`, `KEY code value`, `HOVER` dropped v1) → container `InputFlinger` injection (`InputReader` policy patched to accept `halide-input` device id, not go through kernel re-read).

Calibration per SKU (`hw/<sku>/input-matrix.conf`): 3×3 transform + rotation flag; procedure: draw 5-point cross-hair app on host, tap each 3×, solve least-squares, verify residual <8px at panel native resolution; store matrix + residual in repo. Palm rejection: width>18mm + pressure profile → mark `TOOL_PALM`, drop unless 2+ fingers (documented heuristic with false-reject test: 100 intentional edge-swipes, <3 dropped).

Keyboard (USB/BT): host grabs, forwards Android keycodes via same socket (`KEY_HOMEPAGE`→`KEYCODE_HOME` mapping table committed; unmapped keys logged once per boot, not spammed). Stylus v1: pressure forwarded, tilt dropped with documented gap.

Latency measurement (binding): `evtest` timestamp (kernel event) → `frame_callback` timestamp (photon-adjacent; true photon needs photodiode — lab quarterly). Budget <100ms p95 over 200 taps; trace archived as `graphics/<sku>/touch-latency.csv` (columns: event_us, present_us, delta_ms, surface). Any MR touching composer/input must attach a fresh 200-tap run or explain why not.

## 8. Modesetting, backlight, color, suspend

Modeset: single panel mode from DT/EDID (`preferred`); no userspace mode enumeration to Android (container sees fixed `DisplayInfo` matching panel — no phantom 4K display). Backlight: host `backlight` class 0–255 mapped linearly to Android 0–255 `LightsService` (both sliders same truth; measure 5 points with lux meter, record curve — cheap panels are nonlinear, document don't fake). HBM/high-brightness outdoor mode: host-owned, Android `SCREEN_BRIGHTNESS` capped (no independent HBM from container — thermal rule).

Color: host `gammastep`/night-light owns DEGAMMA/CTM; Android Night Light package disabled via overlay (two color managers fighting = orange wars). Wide-color: report panel gamut once (colorimeter if lab has one, else datasheet) — no wide-color claims without measurement.

Suspend with display: `wl_surface` visibility false on panel-off → composer sends `onPause` hints to visible Android tasks within 500ms (power rule; verify with `batterystats` wakelock drop). Resume: re-import buffers (gralloc handles may have been reclaimed — expect `stale buffer` path, tested by 50-cycle script in ch.03 §17 with composer running).

## 12. Vsync, scheduling & power (the invisible third of graphics work)

Composer present thread: `SCHED_FIFO` prio 10 (below audio IRQ thread, above drawer daemon — priority map committed in `graphics/prio-map.txt`, PI-futex audit quarterly). Vsync source: DRM `vblank` event (not timer-guess — timer presenters drift into permanent 1-frame-late). Missed-vblank accounting: `MISSED_VBLANK` counter with per-minute histogram (nightly uploads feed the jank dashboard; regression >2% week-over-week pages graphics owner). Panel self-refresh (PSR): enabled where panel supports (measure the win: 30-min static-screen current with/without — if <5mA, complexity stays OUT with the measurement attached as the reason).

## 14. Frame-pacing/deadline tracing guide (jank has a timeline — read it)

Trace stack (one method everywhere per ch.01 §16 — this section is that method for graphics): kernel `drm_vblank_event` + `fence_signaled` ftrace, composer present-thread markers (`HALIDE_PRESENT_{acquire,import,commit,callback}` tracepoints via `TRACE_EVENT` or userspace `perfetto` counters — both emitted, joined by `frame_seq`), Phosh/phoc `frame_callback` timestamps, Android `SurfaceFlinger --latency` + `dumpsys gfxinfo <pkg> framestats` (container side). Join key: `frame_seq` (monotonic per surface; SEQ-joined like ch.06 §7 touch-latency CSV — `graphics/<sku>/frame-join.csv` columns: `seq,acquire_us,import_us,commit_us,callback_us,sf_latency_us,delta_ms,missed_bool`).

Capture procedure (lab, REF-A sacrificial): (1) start `halide-frame-trace --duration 30 --surface android.<pkg> --out trace-<date>/` (wraps ftrace + perfetto + gfxinfo polling with synchronized `CLOCK_MONOTONIC` — three clocks problem solved by one tool), (2) scripted workload (F-Droid list fling ×5 + 720p video 60s + drawer open/close ×10 — same workload every release, committed as `graphics/workload-jank.sh`), (3) `halide-frame-report` emits: missed-vsync %, p50/p95 frame time, fence-wait histogram, import-time histogram, top-3 stall causes (fence-wait vs import vs callback-late, auto-classified). Pass bars (§10 matrix restated as numbers): scroll <5% missed, p95 ≤20ms at 60Hz panel, fence-wait p95 ≤8ms (higher = driver/icc problem per §9 concurrent-video row, not composer).

Deadline discipline: composer present thread wakes on `vblank - 2ms` (margin for import+commit; margin measured per SKU — panels with slow DSI need 3ms, recorded in `panel.json` extension `present_margin_ms`), missed-deadline path (present previous good frame + `MISSED_VBLANK`++ per §12 — never block into the next vblank holding a fence; blocking cascades into permanent 1-late). Triage ladder for red traces: fence-wait heavy → driver sync/icc (§9); import heavy → modifier negotiation (§6 — unsupported modifier fallback path costs ms, allowlist gap); callback-late → compositor (phoc) overload or prio inversion (`prio-map.txt` §12 + `PI-futex` audit); SF-latency heavy → container-side (gralloc dequeuing slow — HAL stride/format §9 before composer blame).

CI/lab split: VIRT nightly runs workload-jank headless (trend only — virtio-gpu timings not gate-worthy, stated twice per §10 honesty rule); HW weekly + pre-release produce the signed `frame-join.csv` + report archived per SKU (release notes link the jank numbers like compat hit-rate — "v1.4 scroll 2.1% missed, −0.8 vs v1.3").

## 16. Screenshot/screen-record architecture (one pipeline, both stacks, no double-color)

Screen capture paths (single-color-pipeline rule §8/§9 enforced here): stills via host `grim`-equivalent on the compositor output (post-CTM pixels = what the eye sees — the honest screenshot); container `screencap` used only for A/B color-agreement tests (§10 row — agreement proves single application of CTM, persistent disagreement means double-application and blocks the gate). Screen-record: host `wf-recorder`-class (hardware-encode where `msm` VPU exposes encode — else CPU with resolution cap documented; encode load measured against concurrent-video gate §10 so recording doesn't silently void the underrun guarantee). Android-side `screenrecord` binary present for HAL debugging only (output labeled `container-side-uncolored` — never user-facing, never compared to host captures as equals).

Privacy & consent (load-bearing — screenshots see everything): capture APIs gated by polkit (`org.halide.capture` — foreground-app consent dialog naming the requesting package, both stacks; background capture without visible indicator banned — indicator LED/icon owned by host compositor, not requestable by container). DRM-flagged surfaces (L3 playback §13): compositor blanks to black in captures (verified by L3-sample screenshot test — green/recorded-content leak = P0). Work-profile/multi-user note (§13 drawer edge adapted): hidden packages never appear in host captures of another surface (occlusion-tested in overlay-attack row §10 extended to capture path).

Redaction for bug reports (feeds log-export ch.05 §19 bundle): `halide-screen-redact` (blur regions from a tap-to-mask UI before attach; EXIF/location stripped; capture metadata embedded: build ID, panel variant, CTM state, compositor commit — a screenshot without build metadata is undebuggable and the tool refuses to export it bare). Support roleplay (ch.01 §18) includes a capture-redact drill (confused-user sends banking screenshot — agent must request redacted re-capture via the tool, never accept raw PII).

## 17. Display power deep-dive (the panel is the battery — measure it like one)

## 18. Backlight PWM/dimming deep-dive (flicker never ships to save milliamps)

Dimming modes per panel variant (`panel.json` extension `dimming: {mode: pwm|dc|hybrid, pwm_hz, min_duty_pct, dc_crossover_nits}`): PWM frequency measured (photodiode + scope, not datasheet — datasheet PWM numbers describe the driver IC maximum, the panel integration divides; measured value committed with scope screenshot + probe setup photo so the next engineer reproduces rather than trusts). Flicker bars: PWM <500Hz below 50% duty rejected (camera-visible banding per ch.03 §13 240fps test + human-factors headache reports — the bar is written down so schedule pressure can't renegotiate it silently); DC-dimming crossover documented where supported (color-shift vs current measured with colorimeter or datasheet + `measured:false` amber flag per §11); hybrid (PWM-high + DC-low) preferred where hardware allows with crossover hysteresis (±10 nits — crossover hunting oscillates brightness visibly and the hysteresis value is asserted in test).

Test procedure per release (`graphics/<sku>/flicker-test.md` checklist): 240fps phone-camera capture at 10/25/50/100% slider (banding absent = pass, frames archived 30 days), lux-meter linearity (5+ points into backlight curve §8 — PWM-low-end nonlinearity corrected in the software curve, correction table committed), suspend/resume backlight restore (pre-suspend level restored ±1 step within 1s of resume — resume-to-full-blast in a dark room fails UX review + power review simultaneously). Failure ladder: banding at low % → raise PWM floor or switch crossover first (never "document as known" without a BUG + affected-variant list — flicker sensitivity varies by user and the honest path is a fix or a variant-specific floor, not a footnote).

## 19. GPU hang/fault recovery (the GPU will hang — recovery is designed, not hoped)

Detection layers (fastest first): composer watchdog (§6 — no present 2s while visible → fence-timeline dump), DRM `GPU fault`/`hangcheck` dmesg signatures (pattern file `graphics/HANG-SIGNATURES.txt`: `freedreno.*hang`, `msm.*fault`, `sync_file.*timeout` — journal alert rule matches these with `HANG-SUSPECT` field for dashboard counting), kernel hangcheck IRQ (recovers or escalates to `drm_offload` per driver capability — capability per SKU recorded: Adreno recovery-capable vs Mali-blob informational per §2 timebox note). Recovery ladder (each rung logged + user-visible state): L1 soft (composer re-import + re-commit current buffers — transient fence storm per §10 injection test, automatic, counted in stall metric), L2 context reset (drop the offending surface's buffers, present placeholder + "App graphics restarted" notice — app survives, screenshot of pre-reset frame attached to bugreport), L3 container display-service restart (`halide-display-restart` §9 — Android SystemUI/SurfaceFlinger virtual display cycled, host Phosh untouched, running native apps unaffected — the isolation that justifies the hybrid architecture), L4 full container restart (ch.05 §2 crash policy counts this toward the 3-crash banner — GPU wedges that reach L4 are container-stability bugs with BUG IDs, not "graphics flakiness").

Forensics bundle (`halide-gpu-forensics` on any L2+: fence timeline + `dmesg` DRM slice + `sysprof`/perfetto GPU counters + `frame-join.csv` tail (§14 — hang-cause classification starts from the same timeline as jank) + `lshal`/HAL state for camera-preview hangs (§9 stride/modifier suspects). Fault-injection CI (§10 fence-drop harness extended): GPU-fault sysfs injection on eng (where driver exposes `hang` testpoint) + compositor-kill drill (phoc restart must not strand Android surfaces — re-import path exercised, FD-leak counter §10 asserted zero-delta after). Hang-rate gate: >1 L2+/week on dogfood fleet = P1 against the GPU driver/panel combo (hangs normalized per device-week like RMA rates ch.02 §18 — "rare" with a denominator or it didn't happen).

## 20. Touch-firmware/composer interaction log (two tunables, one finger)

## 29. Fence/FD-leak detection runbook (sync_file counters, lsof/drm leases, soak thresholds)

FD leaks are the slow black-screen (§5 `zwp_linux_dmabuf_v1: no memory` row + §10 FD-leak row made executable). Every present cycle moves 3 FDs minimum (dma-buf import + acquire `sync_file` + release `sync_file`); any path that opens without close grows `/proc/$(pidof halide-composer)/fd` monotonically until the compositor, then the session, then the bug queue dies. This section is the normative runbook: what to count, where to look, what number fails, and the exact fix routing. All commands run on host unless marked `(container)`.

FD classes owned by `halide-composer` (close discipline per class — review-bounced if a new FD type arrives without a row here):

| Class | Origin | Close site | Leak signature | Distinguish |
|---|---|---|---|---|
| `dmabuf` | binder RX from SF proxy (`recvmsg` SCM_RIGHTS) | after `wl_buffer.destroy` post-`release` event | `anon_inode:dmabuf` count grows with task open/close | vs GPU GEM leak (see `drm_gem` row — dmabuf-only growth = composer release path, both grow = driver) |
| `sync_file:acquire` | binder RX alongside buffer | after `poll()` returns + import commit (≤1 present cycle lifetime) | `anon_inode:sync_file` + `sync_file info` fence never signaled | signaled-but-open = close-path bug (fix composer); never-signaled = driver stall (§6 stall metric, not a leak) |
| `sync_file:release` | created at `wl_surface.commit` (compositor returns via `release` event) | on `frame_callback` return to producer (close after send, or close after `sendmsg` fail) | release count 2× acquire at steady state | send-fail without close = error-path leak (fault-inject `sendmsg` ENOMEM in CI to prove) |
| `drm_gem_handle` | `DRM_IOCTL_PRIME_FD_TO_HANDLE` during import | `DRM_IOCTL_GEM_CLOSE` on release | `/sys/kernel/debug/dri/0/gem` objects grow, `drm_clients` same pid | GEM-only growth with flat FD = kernel-handle leak (driver path, file BSP bug with gem dump) |
| `wayland_shm/eventfd` | `wl_display` connect + present-thread `eventfd` | process exit only (constant) | growth on `halide-display-restart` cycles | restart-path double-connect (fix restart, not present loop) |
| `binder_transaction_fd` | SF proxy layer-list updates | end of binder txn handler | `binder stats` pending-transactions grows | proxy batching change suspect (bisect proxy build) |

Counters (read all four — one counter lies, four triangulate):

1. `ls -l /proc/$(pidof halide-composer)/fd | wc -l` (coarse total; record at t0/t1 around any repro; delta is the gate, absolute varies by surface count — baseline file `graphics/<sku>/fd-baseline.txt`: `surfaces:N total_fd:M dmabuf:K syncfile:J` per standard workload `workload-jank.sh` §14 so deltas compare against same-N).
2. Per-class breakdown (the command that names the class — run before/after, diff is the diagnosis): `ls -l /proc/$(pidof halide-composer)/fd | sed 's/.*-> //' | sort | uniq -c | sort -rn` plus `for f in /proc/$(pidof halide-composer)/fdinfo/*; do grep -H 'inotify\|eventfd\|sync\|dmabuf' $f; done` summarized by `halide-fd-classes --pid $(pidof halide-composer)` (checked-in script — counts `anon_inode:[dmabuf|sync_file|drm]`, `socket:[binder]`, `eventfd`, `drm` nodes; output CSV `ts,pid,total,dmabuf,syncfile,gem_est,binder,eventfd` appended to `graphics/<sku>/fd-soak.csv` during soaks).
3. `sync_file` liveness (distinguishes stall vs leak — leaked acquire fences stay open AND signaled; stalled stay open UNSIGNALED): `grep -r . /sys/kernel/debug/sync/sw_sync 2>/dev/null | head -20` where `sw_sync` exposed, else `halide-fence-dump --pending` (composer debug endpoint `--debug` §5: lists last 16 fences `seq,acquire_fd,signaled_bool,age_ms,producer_task`; signaled+age>5s+still-open = LEAK verdict, unsignaled+age>500ms = STALL verdict per §6 500ms timeout — the dump prints the verdict word so triage doesn't re-derive it).
4. DRM leases/clients + GEM objects (host DRM truth — catches the GEM-handle half): `cat /sys/kernel/debug/dri/0/clients` (composer entry: `pid,uid,master:N,open:1` — second master attempt = `-EBUSY` architecture violation §1, file P0), `ls /sys/kernel/debug/dri/0/gem 2>/dev/null || cat /sys/kernel/debug/dri/*/gem_objects` (object count + per-handle `size,imported:Y/N`; imported-grows-while-FD-flat = `GEM_CLOSE` missing), `drm_info -j | jq '.clients'` archived per soak (lease churn on DP-alt-mode SKUs §15: external-output present thread opens/closes per modeset — lease count must return to baseline after unplug or the §15 sketch regresses v1 panel path).

`lsof`/`ss` companions (when fdinfo is ambiguous): `lsof -p $(pidof halide-composer) -nP | awk '{print $5,$9}' | sort | uniq -c` (TYPE/NAME histogram — `FIFO` growth = input-socket backpressure §7, not graphics; `REG` growth = screenshot/capture temp files §16 `halide-screen-redact` not cleaning); `ss -x -p | grep halide` (input socket + SF-proxy socket queue depths — `Recv-Q` pinned >64KB across a soak = proxy batching stall feeding apparent FD growth; fix proxy, not fences). Container side (SF proxy leak vs host leak isolation): `(container) lsof -p $(pidof surfaceflinger) | grep -c dmabuf` before/after killing one Android task — container count must drop by task buffers within 5s (else the leak is producer-side gralloc, route to HAL per §9 stride/modifier note, not composer).

Runbook (soak → detect → isolate → file — 30-minute lab form):

1. Baseline: boot REF-A sacrificial, start standard workload (`workload-jank.sh` + drawer ×10 per §14), record `halide-fd-classes` t0 + `fd-baseline.txt` N-surfaces note + `frame-join.csv` 60s (soak without the jank timeline can't separate leak-jank from fence-jank later).
2. Task-cycle drill (fast leak screen, 10 min): open/close 1 Android app ×50 (`halide-task-cycle --app org.fdroid --n 50 --interval 4s` — 4s lets release fences return; 1s intervals fabricate stall-leaks, forbidden); assert per-§10 gate `FD delta == 0` (tolerance: total ±2 for shm jitter, dmabuf/syncfile exactly 0 — any positive dmabuf/syncfile delta FAILS, no "small leak" waivers; small leaks kill 8h dogfood days).
3. Soak (slow leak screen, 60 min minimum, overnight for releases): `halide-fd-soak --duration 3600 --sample 30 --out fd-soak.csv` (samples §counters-2 CSV + `MISSED_VBLANK` + stall count per §12/§6; workload loop: video 10 min + scroll 5 min + static 5 min rotating — static phase catches PSR-exit fence retention §28 `PSR-EXIT` label vs leak confusion: PSR-hold fences release within 1 frame of exit, leaks never release).
4. Threshold evaluation (numbers that page — committed in `graphics/<sku>/fd-thresholds.conf`): WARN if `total` slope >4 FDs/hour over any 2h window; FAIL if `dmabuf+syncfile` slope >0 over 1h (zero-tolerance classes), or `total` delta >+10 after task-cycle ×50, or GEM objects +>5 after display-restart ×3 (`halide-display-restart` §9 must be FD-neutral — restart that fixes black-screen by leaking is a loan shark fix). Slope computed by `halide-fd-report fd-soak.csv` (least-squares + verdict line `PASS/WARN/FAIL(<class>:<slope>/h)` — the report string pasted into release-notes graphics figures §21 `FD-delta` cell; `NOT-MEASURED` if the soak CSV hash missing).
5. Isolate (on WARN/FAIL): freeze workload, run `halide-fence-dump --pending` (LEAK vs STALL verdict §counters-3) + `drm_clients` + GEM snapshot; kill ONE Android task (if dmabuf drops = per-task release path, suspect `wl_buffer.destroy` ordering; if flat = global/import path, suspect modifier-fallback buffers §6 that bypass the normal release arm); toggle PSR off (`panel.json psr.enabled=false` + reboot — if slope zeroes, the PSR-exit path holds fences, route to §28 handshake owner); restart display service only (`halide-display-restart` — if counts reset to baseline, leak is in per-display state (surface map), if they persist, leak is in global import context (compositor connection state)).

## 30. Touch-latency SEQ-join CSV method worked example (evtest + frame_timeline join, 200-tap stats, p50/p95 calc)

This section makes §7's binding latency method reproducible by a new hire with a stopwatch-hostile lab: exact capture commands, the SEQ-join (same join-key doctrine as §14 `frame_seq` — here the key is tap `seq`), a 12-row worked excerpt with real-shaped numbers, and the p50/p95 calculation done longhand once so the script is never a black box. Budget restated: touch→`frame_callback` p95 <100ms over 200 taps per SKU; trace archived `graphics/<sku>/touch-latency.csv`; any composer/input MR attaches a fresh run or a why-not reviewed by the graphics owner.

Clock doctrine (one clock or the numbers are fiction): kernel `evtest` event timestamps (`struct timeval`, `CLOCK_MONOTONIC`-adjacent via `EVIOCG` path — actually `CLOCK_REALTIME` in older kernels, converted), composer `frame_callback` timestamps (`CLOCK_MONOTONIC` via `clock_gettime`), join tool normalizes both to `MONOTONIC_US` at capture start (offset sample: `halide-touch-trace` reads `/proc/uptime` + `clock_gettime(MONOTONIC)` + `gettimeofday()` triple within 100µs and commits the offsets in the CSV header `# monotonic_us = realtime_us - <offset_us>, captured <iso8601>, sku, panel_variant, build_id`). True-photon note (§7 restated with the workaround): `frame_callback` fires ~1 frame before photons (scanout latency per §25 margin 1–4ms); lab-quarterly photodiode adds `photon_us` column and the release-notes p95 cites `present_us` with the scanout footnote unless the diode run exists — no silent substitution of callback numbers for photon claims.

Capture procedure (lab, REF-A, same unit + bench discipline as §20 — accessory-golden cables per ch.02 §21, charger-unplugged (charging noise §23 inflates palm-reject + latency tails simultaneously and the run is invalid), night-light off (§22 CTM adds ≤1ms but adds variance — variance is the enemy of p95)):

1. `sudo halide-touch-trace --duration 300 --out touch-run-<date>/ --tap-prompt audio` (wraps: `evtest /dev/input/eventX` filtered to `BTN_TOUCH`+`ABS_MT_SLOT` device from `hw/<sku>/input-matrix.conf`, `halide-composer --trace-present` markers `HALIDE_TOUCH_COMMIT/CALLBACK` with per-tap `seq`, metronome beep every 1.5s for 200 taps ≈ 5 min; operator taps the highlighted crosshair with a capacitive stylus (finger capacitance varies tap-to-tap ±8ms apparent pressure-threshold crossing — stylus نارrows the input variance so the measured tail is the stack's, not the finger's; 20 of the 200 taps finger-taps at the end as a realism appendix, labeled `tool:finger` vs `tool:stylus`)).
2. Raw outputs: `evtest.log` (kernel lines), `present.log` (composer markers), joined by `halide-touch-join --evtest evtest.log --present present.log --matrix hw/<sku>/input-matrix.conf --out touch-latency.csv` (join key: temporal SEQ — each `BTN_TOUCH down` (value 1) opens tap `seq=N`; first `HALIDE_TOUCH_COMMIT` after `down` on the hit-tested Android surface (§7 hit-test) with same `slot` closes the `commit_us`; first `frame_callback` after commit closes `present_us`; taps with a second `down` before commit (multi-finger contamination) flagged `contaminated:1` and excluded from stats but counted in the header `# excluded_contaminated:K/200` — K>10 invalidates the run (operator re-takes, no silent filtering of slow taps as "contaminated")).
3.
